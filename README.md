# 4-DOF arm: hand-tracking control with mono and stereo vision

Control a 4-servo robot arm from a computer, either with the keyboard or by moving your own arm in front of a camera. The project also includes a calibrated two-webcam stereo rig and a test to measure whether stereo depth tracks position better than a single camera.

The arm has two joints, each with two rotation axes (four 180° servos, no end effector):

| Arm joint | Follows | Axes |
|---|---|---|
| Joint 0 | your forearm (elbow → wrist direction) | pan, tilt |
| Joint 1 | your hand (wrist → knuckles), relative to the forearm | pan, tilt |

## How it works

```
camera(s) ─► tracker ─► 3D directions ─► joint angles ─► smoothing + limits ─► serial ─► Arduino ─► servos
```

- **Tracking**: MediaPipe Pose finds the shoulder, elbow and wrist; MediaPipe Hands finds the knuckles. Both run on every frame, because hand tracking alone cannot see the elbow.
- **Depth**, three ways:
  - `mono`: one camera, using MediaPipe's own learned 3D estimate.
  - `stereo` with `--depth disparity`: two cameras; each landmark's depth is read from a dense disparity map.
  - `stereo` with `--depth triangulate`: the arm is tracked in both views and matching landmarks are intersected.
- **Mapping**: angles are measured relative to a neutral pose that you set with a key press; neutral corresponds to 90° on every servo.
- **Safety**: every command passes through per-servo limits, a smoothing filter and a speed limit. Arm output starts paused. If tracking is lost the arm holds its pose, then eases home after one second.

## Hardware

- Arduino (Uno/Nano class) with four servos on pins 9, 10, 11 and 6, powered from a supply that can drive four servos.
- One webcam for mono mode.
- Two webcams fixed rigidly side by side for stereo mode. They can be different models; they must not move after calibration.
- A printed calibration board (generated by this project) glued to something flat.

## Setup

Python 3.12 is required (MediaPipe does not support 3.14).

```bash
py -3.12 -m venv .venv
```

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Flash `4_servo_arm/4_servo_arm.ino` with the Arduino IDE.

The first run of any vision script downloads two MediaPipe model files (about 17 MB) into `models/`.

## Usage

Run everything from the project root.

### 1. Keyboard control and servo setup

```bash
.venv\Scripts\python.exe keyboard_control.py
```

`Q/A`, `W/S`, `E/D`, `R/F` move servos 1–4, `0` resets, `Esc` quits. Add `--port COM3` to choose the port, or `--no-arm` to try the GUI without hardware.

Use this to find out which servo is which axis, then fill in the `servos` list in `config.json`: `role`, `invert`, `offset_deg`, and safe `min_deg` / `max_deg`. The keyboard tool drives raw servo values and ignores these settings; vision control obeys them.

### 2. Vision control, one camera

```bash
.venv\Scripts\python.exe vision_control.py --no-arm
```

Sit so the camera sees your shoulder, elbow and hand. Remove `--no-arm` to drive the arm.

| Key | Action |
|---|---|
| `N` | set the current pose as neutral |
| `Space` | engage / pause arm output (starts paused) |
| `H` | send the arm home and pause |
| `Q` / `Esc` | quit |

### 3. Stereo calibration

Generate the board, print it at 100 % (no "fit to page"), and measure one black square. If it is not the size in `config.json` (`board.square_mm`), enter the measured value and scale `marker_mm` by the same ratio.

```bash
.venv\Scripts\python.exe -m calib.make_board
```

Set the two camera indices in `config.json` (`cameras.left`, `cameras.right`). It does not matter which one you call left; calibration works out the real order.

Capture about 30 pairs with the board near, far, in every corner of the picture and tilted in different directions. `Space` saves a pair.

```bash
.venv\Scripts\python.exe -m calib.capture_pairs
```

```bash
.venv\Scripts\python.exe -m calib.calibrate
```

Calibration prints a verdict for each camera, for the stereo fit and for row alignment, plus the baseline to compare against a ruler. It also writes `calib/rectified_check.png`: each green line should cross the same features in both halves. Recalibrate whenever the rig is moved.

### 4. Vision control, two cameras

```bash
.venv\Scripts\python.exe vision_control.py --mode stereo --no-arm
```

```bash
.venv\Scripts\python.exe vision_control.py --mode stereo --depth triangulate --no-arm
```

The window shows each landmark's distance in cm next to the colour disparity map. Depth cannot be measured closer than roughly 27 cm with the default settings.

### 5. Mono vs stereo comparison

Tape a 3×3 grid of marks on the table, 10 cm apart, and measure them. The layout lives in `config.json` under `eval.targets_cm` (x across, y up, z away from you, in cm; the origin is arbitrary).

```bash
.venv\Scripts\python.exe -m eval.record
```

For each target, put your index fingertip on the mark with your elbow, forearm and hand in view, press `Space` and hold still. `B` redoes the previous target, `S` skips, `Q` finishes. Every frame is measured by all three methods at once, so they see exactly the same motion.

```bash
.venv\Scripts\python.exe -m eval.analyze
```

This prints a comparison table and writes `summary.csv`, `accuracy.png`, `jitter.png` and `layout.png` to `eval/results/<session>/`.

| Metric | Meaning |
|---|---|
| Position error | distance between where a method put the targets and where they really are, after the best rotation and shift; split into depth and lateral |
| Size scale | how much the method over- or under-estimates real size (1.00 is correct) |
| Jitter | spread while holding still, for positions and for the commanded joint angles |
| Frames with no reading | how often the method produced nothing |
| Processing time | per-frame cost, and the frame rate that allows |

## Configuration

Everything is in `config.json`.

| Section | Purpose |
|---|---|
| `serial` | port (`null` = auto-detect) and baud rate |
| `servos` | per-servo role, direction, offset, limits, home angle, speed limit |
| `cameras` | camera indices and resolution |
| `board` | calibration board geometry |
| `stereo` | disparity matcher settings |
| `mapping` | which arm to track (`right` or `left`), per-joint gains, hold time on tracking loss |
| `eval` | target layout and timing for the comparison |
| `filter` | smoothing strength (lower `min_cutoff_hz` = smoother but laggier) |


## Serial protocol

One ASCII line per update at 115200 baud: four integers from 0 to 1023 separated by commas, ending in a newline.

```
512,512,512,512
```

0 maps to 180° and 1023 to 0°. The firmware replies `OK` or `Invalid command` to each line and prints `4-servo controller ready!` after reset. If several lines are waiting, only the newest is applied.

## Tests

```bash
.venv\Scripts\python.exe -m pytest -q
```

The tests cover the maths (conversions, limits, mapping, calibration on simulated cameras, depth, and the analysis on a simulated session). They do not need the arm or any camera.

## Known limitations

- Forearm roll (turning the palm over) is not tracked, so the hand's two axes are referenced to the camera rather than to the palm.
- USB webcams are not hardware-synchronised; fast motion smears stereo depth.
- The disparity map struggles on smooth, textureless surfaces such as bare skin or a plain wall.
- Mono depth depends on an assumed hand size.
- Cameras with autofocus must have it disabled, or the calibration silently becomes wrong.
